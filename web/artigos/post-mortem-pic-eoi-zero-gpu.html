Como o EOI Incondicional no PIC 8259A e o Motor Zero-GPU Viabilizaram 0.00% de CPU em Repouso no Jinn OS

Um mergulho técnico nos bugs de congelamento sob carga rápida de mouse/teclado, a armadilha do EOI condicional no x86 legado e como buffers estáticos alinhados a 64 bytes com AVX2 substituíram alocações dinâmicas no compositor gráfico.

Tese de Engenharia

Em sistemas operacionais bare-metal escritos em Rust (#![no_std]), a ilusão de que o código seguro impede travamentos de baixo nível desmorona na fronteira do hardware. Se a ISR (Interrupt Service Routine) falha em sinalizar o término da interrupção (EOI) sob qualquer condição de saída, a linha INTR do processador permanece travada, mascarando todas as IRQs subsequentes de menor ou igual prioridade.

1. O Sintoma: Congelamento Parcial em Sessões Interativas

Durante os testes de estresse no QEMU e VirtualBox com 4 vCPUs e o compositor gráfico Aladdin Desktop operando em Ring 3, observamos um comportamento anômalo: após 5 a 15 segundos de movimentação vigorosa do cursor PS/2 combinada com digitação rápida no terminal, o sistema deixava de responder a novas entradas.

Curiosamente, os contadores do timer PIT (IRQ 0) continuavam incrementando e os daemons de fundo permaneciam ativos, mas nenhum pacote de mouse (IRQ 12) ou teclado (IRQ 1) chegava às filas de eventos de usuário. A telemetria apontava que o microkernel não estava em kernel panic; ele simplesmente havia ensurdecido para o subsistema de entrada.

2. A Causa Raiz: A Armadilha do EOI Condicional no PIC 8259A

No PC/AT padrão, o controle de interrupções legadas é gerenciado por dois controladores PIC 8259A em cascata (mestre nas portas 0x20/0x21 e escravo nas portas 0xA0/0xA1). O mouse PS/2 conecta-se à IRQ 12 (linha 4 do escravo, roteada pela IRQ 2 do mestre).

No código original da ISR em Rust, havia uma verificação defensiva prematura: 

// ANTIGO (BUG): EOI condicional apenas se houvesse dados válidos no buffer
let status = inb(0x64);
if (status & 0x01) == 0 {
    // Retornava imediatamente sem sinalizar o PIC!
    return;
}
// ... processava pacote ...
pic::send_eoi(12);

Quando múltiplos eventos de hardware ocorriam em rápida sucessão, uma leitura espúria ou estado intermediário fazia com que a rotina retornasse sem enviar o comando End of Interrupt (0x20). Como consequência, o bit correspondente no registrador ISR (In-Service Register) do 8259A permanecia em 1. O hardware assumia que a interrupção ainda estava sendo processada e bloqueava categoricamente qualquer nova interrupção daquela linha.

A Correção Definitiva

O envio de EOI deve ser incondicional e colocado em bloco finally/garantido antes de qualquer retorno. Para qualquer IRQ do controlador escravo (IRQs 8 a 15), o EOI deve ser despachado primeiro para a porta 0xA0 e logo em seguida para a porta mestre 0x20: 

// CORREÇÃO DEFINITIVA (Commit a2fc85e): EOI Incondicional
#[no_mangle]
pub extern "x86-interrupt" fn ps2_mouse_handler(_stack_frame: InterruptStackFrame) {
    let _guard = crate::interrupts::pic::PIC_LOCK.lock();
    
    // Leitura segura do status e dreno do registrador de dados (0x60)
    let status = unsafe { inb(0x64) };
    if (status & 0x01) != 0 {
        let scancode = unsafe { inb(0x60) };
        crate::interrupts::ps2_mouse::enqueue_raw_byte(scancode);
    }
    
    // EOI INCONDICIONAL: Escravo primeiro, depois Mestre
    unsafe {
        outb(0xA0, 0x20); // EOI Slave (IRQ 12)
        outb(0x20, 0x20); // EOI Master (Cascata IRQ 2)
    }
}

3. A Segunda Frente: Motor Vetorial Zero-GPU no JHCS

Com as interrupções de hardware estabilizadas, restava o segundo grande desafio de sustentabilidade: o consumo de CPU em repouso. O Aladdin Desktop implementa efeitos visuais contemporâneos (frosted glass, sombras de elevação em camadas, reflexos espelhados no dock e redimensionamento dinâmico de janelas clientes).

Em um sistema tradicional, essas operações são delegadas à GPU via shaders OpenGL ou Vulkan. No Jinn OS, operamos sob a restrição Zero-GPU: toda a composição gráfica deve rodar na CPU, sem alocar memória no laço quente e sem manter threads em polling ocupado.

Estrutura Estática em .bss

Eliminação total de alloc::vec::Vec nos filtros de imagem. Buffers de trabalho alinhados a 64 bytes pré-alocados em .bss (STATIC_SCRATCH), eliminando pressão no alocador do microkernel e prevenindo fragmentação de heap.

Kernels AVX2 + FMA de 256 bits

Processamento de 8 pixels RGBA por instrução vetorial (_mm256_fmadd_ps) com fallback dinâmico em tempo de execução via CPUID para SSE2 em máquinas legadas.

O isolamento dos estados SIMD entre tarefas é garantido pela Syscall de troca de contexto com fxsave64 e fxrstor64 sobre buffers dedicados de 512 bytes alinhados a 16 bytes na estrutura Task do escalonador.

4. O Resultado: Rank 1 e 0.00% de CPU em Repouso

A combinação dessas duas soluções produziu métricas sem precedentes para o ecossistema Jinn OS:

  • Consumo Ocioso (Zero-Idle): Medição de 0.00% de utilização de CPU nas 4 vCPUs no monitor do QEMU após a estabilização da interface gráfica.
  • Desempenho de Janelas: Redimensionamento fluido em tempo real com grips de 6px e despacho síncrono de EVENT_WINDOW_RESIZE.
  • Estabilidade de Longo Prazo: Mais de 100.000 eventos de teclado e mouse injetados sem um único congelamento ou descarte de IRQ.
