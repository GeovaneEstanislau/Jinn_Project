Construindo um Navegador Web Nativo sobre Microkernel: Do Socket TCP ao Motor CSS Cascata e DOM Reativo em Rust Puro

Os bastidores da criação do Jinn Browser: como um executável de 370 KiB em Ring 3 implementa HTTP/1.1 com redirecionamentos, resolução DNS cascata, parser CSS com especificidade e execução reativa de scripts.

Capacidades do Jinn Browser

  • Binário Único sem Dependências: browser.elf executa inteiramente em Ring 3 usando as syscalls canônicas do Jinn OS.
  • Pilha HTTP/1.1 Completa: Resolução de DNS em cascata (Cloudflare, Google, SLiRP), 3-way handshake TCP, keep-alive e suporte a até 5 redirecionamentos (HTTP 301/302).
  • Motor CSS com Cascata e Especificidade: Seletores por tag, classe, ID e descendência com cálculo de Box Model, Flexbox (linha) e bordas arredondadas.
  • Runtime JavaScript Reativo: Suporte a eventos de clique (onclick, addEventListener), manipulação do DOM e re-renderização imediata de layout.

1. O Pipeline do Navegador: Da URL aos Pixels na Tela

Criar um navegador a partir do zero em um ambiente bare-metal sem libc é um dos maiores desafios da engenharia de computação. No Jinn OS, o pipeline do navegador foi estruturado em 5 fases determinísticas:

  1. Resolução de Rede: sys_dns_resolve traduz o domínio para IPv4 e sys_socket + sys_connect estabelecem a sessão TCP.
  2. Dreno de Payload HTTP: O cliente consome chunks de dados até encontrar \r\n\r\n e valida Content-Length ou encerramento de conexão.
  3. Construção da Árvore DOM: O parser HTML converte a sequência de bytes em nós indexados em arena estática (DomArena).
  4. Resolução CSS em Cascata: Folhas de estilo <style> e atributos style="..." são ordenados por especificidade (Inline > ID > Classe > Tag).
  5. Composição e Apresentação: Os nós visíveis geram caixas de layout (BoxRect) desenhadas diretamente no backbuffer e transferidas ao compositor Aladdin com sys_window_update.

2. Cascata CSS e Suporte a Layout Flexbox

Em apps/ola-mundo/src/browser.rs, o motor CSS implementa a resolução completa de estilos em tempo determinístico: 

// Especificidade estrita: Tag (1) < Descendente (2) < Classe (10) < ID (100) < Inline (1000)
pub fn resolve_node(&self, dom: &DomArena, node_idx: usize, style: &mut ComputedStyle) {
    self.apply_tag_defaults(dom, node_idx, style);
    self.apply_tag_rules(dom, node_idx, style);
    self.apply_descendant_rules(dom, node_idx, style);
    self.apply_class_rules(dom, node_idx, style);
    self.apply_id_rules(dom, node_idx, style);
    self.apply_inline_styles(dom, node_idx, style);
}

Elementos com display: flex distribuem automaticamente suas caixas filhas horizontalmente, permitindo layouts contemporâneos de cartões, botões em linha e barras de navegação responsivas.

3. Execução Reativa de Scripts sem Dependências Pesadas

O runtime MiniJsRuntime avalia scripts embutidos e associados a eventos de clique. Quando um botão dispara classList.toggle('hidden') ou modifica textContent, o flag dom_dirty é acionado, forçando um novo ciclo de cascata e re-layout visual sem qualquer engasgo.
